# harness.tool.v1

Канон контракта вызова инструмента. Хаб этот каталог по сети не скачивает и JSON Schema не компилирует: вход и выход проверяет ручной строгий zod. Отдельного репозитория контракта нет. Ajv не используется.

Версия записана в `VERSION`.

Длины строк в этой схеме — кодпоинты Unicode, как `maxLength` в JSON Schema, не единицы UTF-16. Эту схему нельзя проверять валидатором, который считает UTF-16. У поля `error` потолок длины один: `maxLength`. Паттерн не задаёт второй потолок.

## Состав

- `harness.tool.v1.request.schema.json`, `harness.tool.v1.response.schema.json`, `harness.tool.v1.http-error.schema.json` — конверт.
- `harness.services.v1.schema.json` — локальный манифест, который кладёт оператор. Истина для хаба — этот файл. Обнаружения инструментов по сети нет.
- `tools/` — вид для ревью `read_file`, `list_dir`, `record_note`. Если эти файлы дублируют манифест, они совпадают с записью в `examples/services.json`. Расхождение валит тест. Хаб список для модели берёт из манифеста, не из `tools/`.
- `examples/` — фиктивные uuid. Значений секретов и Authorization нет. `http://127.0.0.1:9/` в примере — не адрес установки.
- Код рядом — ручная копия конверта и чистая сверка идемпотентности. Таблицы сервиса здесь нет.

Воркер и раннер этот каталог не импортируют и сервис отсюда не вызывают. HTTP файлового сервиса и хранилища блобов отсюда не уходит.

Неизвестное поле конверта не отбрасывается. Чужое значение `contract` — `unsupported_version`. Лишнее поле при верной версии — `unknown_field`.

## Имя для модели

Имена остаются `read_file`, `list_dir`, `record_note`. Они не называются `files.read_file`. Отдельное поле имени для модели допустимо, но эти три инструмента его не задают: для модели имя — поле `name`.

Конверт запроса содержит `service`. Это короткое имя с тем же алфавитом, что `id` сервиса в манифесте. Хаб выбирает сервис по паре `service` и `name`. Если два сервиса отдают одно и то же имя для модели, разбор манифеста не проходит и текст ошибки называет это имя.

## Манифест

У описания инструмента есть `version`. Хаб принимает только известные версии. Сейчас это строка `1`. Неизвестную версию он не игнорирует и не подменяет последней.

`auth.type` равен `bearer` или `none`. `hmac` нет. `none` только если `base_url` — `http://127.0.0.1` с портом. `localhost` не подходит: нужен http://127.0.0.1, не localhost. Секрет в манифест не пишется. Для `bearer` поле `env` — имя переменной окружения, не значение.

В параметрах массива нет сознательно. Ключевого слова `maxItems` нет: `items` запрещён, и `maxItems` ничего не ограничивает. Несколько значений идут строкой или blob. `string[]` нет.

## Ответ и blob

Рядом с человеческой строкой `error` стоит `error_code`. Набор закрыт: `invalid_args`, `not_found`, `forbidden`, `too_large`, `conflict`, `unavailable`, `internal`. Неизвестная строка при разборе становится `internal`. `path_escape` отдельным кодом нет. Строка `error` остаётся.

Id в `blobs` успешного ответа принадлежит хабу. Сервис сначала отдаёт байты хабу и возвращает его id. В контракте нет GET блоба на `base_url` сервиса и нет `blobs_url`. HTTP хранилища хаба этот каталог не описывает.

## Идемпотентность

Ключ записи — `<run_id>:<tool_call_id>` внутри кавычек заголовка `Idempotency-Key`. В аргументы `record_note` этот ключ не возвращается.

`parseToolCall` сам снимает `idempotency_key` из аргументов и только потом строго проверяет. Хеш считается по телу, которое уйдёт сервису, уже без этого ключа. Два вызова с одним и тем же `path` и `text`, где в одном есть лишний `idempotency_key`, не дают `idempotency_conflict`.

`parseToolArguments` — схема, которую видит сервис. Оставшийся `idempotency_key` там — `unknown_field`.

Тот же ключ и то же каноническое тело дают тот же ответ. Тот же ключ и другое тело — 409 `idempotency_conflict`. Чтение побочного эффекта не имеет: для `effect: read` сверка хранилище не читает.

Идентификаторы в конверте — строки. `chat_id` в теле нет.

## Расхождение с процессом

Имена `path` и `text` совпадают с `src/tools`. У `list_dir` поле `path` необязательное, как в коде.

В `src/tools/record-note.ts` аргумент `idempotency_key` обязателен (1..256). Повтор этого ключа не сравнивает тело и возвращает первый текст. Контракт следует спецификации: у сервиса в аргументах только `path` и `text`.

Потолок `text` в процессе — 65536 символов и 64 КиБ UTF-8. Здесь `maxLength` 32768 кодпоинтов, а тело вызова не больше 32 КиБ. Это жёстче, и разбор аргументов в раннере уже обрывается на 32 КиБ.

## Не инструменты хаба

Jira и длинный текст в `examples/not-hub-tools.md` — примеры того же конверта, не имена из `tools/`. Пример Jira тоже показывает `service`.
