# Не инструменты хаба

Jira и длинный текст ниже — примеры того же конверта `harness.tool.v1`.
Их нет в `contract/tools/`. Хаб эти имена не вызывает и отдельных репозиториев под них не заводит.

Значений Authorization в примерах нет. Идентификаторы — фиктивные uuid.

## Jira

Эффект в манифесте того сервиса был бы `write`. Ключ — `Idempotency-Key` со значением `<run_id>:<tool_call_id>`.
Тот же ключ и то же тело вернули бы первую строку. Тот же ключ и другое тело — 409.
Чужая версия задачу не создаёт. Полей токенов в ответе нет.

```json
{
  "contract": "harness.tool.v1",
  "run_id": "00000000-0000-4000-8000-000000000010",
  "tool_call_id": "call_2",
  "agent_id": "00000000-0000-4000-8000-000000000001",
  "service": "jira",
  "name": "create_issue",
  "arguments": {
    "project": "PROJ",
    "title": "Пример",
    "text": "Короткий текст"
  }
}
```

Ответ сервиса был бы коротким, например `создана задача PROJ-1`. Тело задачи в контекст модели не копируется.

## Длинный текст

Эффект в манифесте — `read` или `write` по смыслу вызова. В модель хаба входит итог не длиннее 8000 кодпоинтов.
Если текст длиннее, в `blobs` лежит id хаба, не тело. Сервис сначала отдаёт байты хабу и возвращает этот id. GET блоба на `base_url` сервиса нет, поля `blobs_url` нет.
Поля расхода токенов в ответе — отказ разбора.
Для записи тот же ключ и тот же хеш вторую генерацию не начинают.

```json
{
  "contract": "harness.tool.v1",
  "ok": true,
  "text": "итог готов",
  "truncated": false,
  "duration_ms": 4,
  "blobs": ["00000000-0000-4000-8000-0000000000aa"]
}
```
