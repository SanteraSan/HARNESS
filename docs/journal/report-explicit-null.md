# Явный JSON null в полях отчёта

## Что было не так

`redactReport` считал любой `null` провалом маски и ставил всему отчёту `invalid`. Явный JSON `null` в поле, где схема уже разрешает «заявления нет» (`claimed_prompt_tokens` и соседние поля), до разбора схемы не доходил. jsonb не писался, колонка заявления оставалась пустой, хотя `text` конверта был годный.

Для массива это уже различалось: `null` элемента сохраняется, а `null` от маски непустого значения роняет блок.

## Как исправлено

В полях объекта явное значение `null` копируется как есть. `null`, который вернула маска непустого значения (запрещённый символ, ключ `__proto__` / `constructor` / `prototype`, провал во вложении), по-прежнему делает весь отчёт `invalid` и не кладёт jsonb. Опущенный ключ в копию не добавляется. `has_model: null` по-прежнему не проходит разбор схемы. Миграций нет.

## Вывод

Явный `null` в разрешённом поле — это значение «числа нет»: отчёт `valid`, ключ есть в jsonb, колонка SQL пустая. Провал маски и отсутствие ключа с этим значением не смешиваются.
