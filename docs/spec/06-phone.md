# 06. Телефон

## Назначение

Два разных размещения. Их нельзя смешивать.

Первое: телефон — клиент хаба, который стоит на своей машине. Путь от телефона до этой машины — туннель. Туннель заканчивается соединением к `127.0.0.1:8787`. Приложение телефона говорит протоколом `04-client-protocol.md`. Сервисы туннель не видят и адрес телефона не получают.

Второе: хаб поставлен на сам телефон, отдельной поставкой, не флагом серверной установки. Контракт тот же: `harness.tool.v2` (`09-tool-v2.md`) и тела HTTP из пункта 4. `MODEL_SLOTS` равен 1. Процесс воркера один. Хаб и здесь не вычисляет `num_parallel`.

Продукт туннеля этот файл не выбирает. Стек UI телефона не выбирает.

## Что в пункт не входит

Нет настройки конкретного клиента туннеля. Нет ключей в этом файле. Нет проброса Postgres, LiteLLM, файлового сервиса и порта картинок. Нет обязанности серверного сервиса самому строить канал до телефона. Нет входящего слушателя на телефонном хабе.

## Правила ядра

`API_LISTEN_HOST` остаётся `127.0.0.1`. Слушать `0.0.0.0` нельзя и ради телефона тоже. Проверка URL в `src/api/server.ts` собирает адрес из пути и ждёт хост `127.0.0.1`. Её не ослабляют ради имени туннеля в заголовке `Host`.

**I7** сохраняется. Обрыв туннеля и закрытие приложения не ставят запуск в `succeeded`. Аренду снимает обычный reap.

**I14** сохраняется на серверной поставке: Telegram не становится транспортом телефона.

**I20** сохраняется. Bearer в журнал туннеля не пишется. Секрет сравнивается так же, как в пункте 4.

Контракт сервиса про туннель не знает. К моменту HTTP сервиса канал между хабом и сервисом уже локальный либо частный по правилам `01-services.md`.

## Технологии

Любой будущий продукт туннеля обязан выполнить требования ниже. Файл продукты не сравнивает и один из них не назначает.

Если продукт туннеля сам использует TLS, проверка сертификата на телефоне включена. `rejectUnauthorized: false` на клиенте телефона запрещён так же, как на хабе. `NODE_TLS_REJECT_UNAUTHORIZED=0` запрещён.

Телефонный хаб — отдельная сборка. Она не обязана поднимать `listen`. Локальный UI вызывает те же поля постановки и чтения внутри процесса: `POST /v1/runs`, `GET /v1/runs/:id`, загрузка blob. Сокета, который принимает сервисы, нет. Маленькая модель — решение установки, не константа репозитория. Учёт токенов делает хаб по `usage` того шлюза, который поставлен рядом.

Секреты телефонной поставки лежат в хранилище ОС: bearer клиента, если он нужен локальному UI, и секрет сервиса, если локальный сервис вообще есть. В репозиторий приложения и в текст модели они не входят.

Стек UI не выбирается. Electron, IPC и `executeJavaScript` к этому репозиторию не относятся и этим пунктом не выбираются.

## Протокол

Телефон-клиент вызывает тот же HTTP, что локальный клиент.

`POST /v1/runs`:

```json
{
  "agent_slug": "clerk",
  "idempotency_key": "phone-1",
  "message": "привет",
  "chat_id": "42"
}
```

Ответы те же: `201` `created`, `200` `replay`, `409` `dialog_busy` с id. `GET /v1/runs/:id` возвращает `{ "run", "steps" }`. Файл, если он есть, уходит в `POST /v1/blobs`, а в постановку попадает `blob_ids`. Bearer — заголовок `Authorization`, не query и не путь туннеля.

Заголовки туннеля в контракт не входят. Хаб не читает отдельный заголовок устройства как замену bearer. Неизвестный заголовок туннеля постановке не мешает только потому, что постановка читает свои поля тела. На маршрутах файлов query по-прежнему запрещён.

Сервисный вызов с машины хаба остаётся `POST /v1/tools/{name}` на `base_url` манифеста. Адреса телефона в этом запросе нет.

Телефонный хаб, если зовёт сервис, делает исходящий вызов по правилам пункта 1: лупбэк телефона либо частный адрес с TLS, приколотым сертификатом и bearer. Чужой сервис к телефону не подключается. Поставка `listen` не вызывает. Входящего сокета нет, поэтому чужой процесс не открывает `POST /v1/blobs/ingest` и не забирает `GET /v1/blobs/:id/content` с телефона. Локальный UI вызывает те же поля постановки, загрузки и чтения функцией внутри процесса. Проверки bearer, размера и способности те же, сокета под них нет.

`GET /health` серверной поставки с лупбэка остаётся `200` без токена. С телефона через туннель тот же ответ не заменяет bearer на `POST`.

## Требования к туннелю

- Шифрование на всём пути от телефона до машины хаба. Открытый трафик через чужую сеть не годится.
- Оба конца узнают друг друга. Факт, что пакет дошёл, входом не считается.
- Вход в API всё равно требует bearer. Туннель его не заменяет.
- Отзыв одного устройства не меняет хеши других клиентов и не меняет секрет сервиса.
- Отзыв одного именованного токена не обязан рвать туннель другого устройства.
- Наружу машины не публикуются порт хаба `8787`, порт базы, порт шлюза модели и порт файлового сервиса. Соседние локальные сервисы тоже не пробрасываются. Наружу смотрит только порт самого туннеля, если продукту он нужен, и этот порт не является портом хаба.
- Проброс — один адрес назначения, `127.0.0.1:8787`. Не подсеть и не диапазон.
- Телефон не открывает слушатель для сервисов хаба. Сервис не получает адрес телефона.
- В журнал туннеля не входят bearer, тело, байты файла и `DATABASE_URL`. Допустимы время, id устройства и код отказа.
- Секрет API не записывается в конфиг туннеля и не вставляется в ссылку или QR как токен HARNESS. Ключ устройства, если он есть, — другой секрет и лежит в хранилище ОС телефона.
- Обрыв туннеля не ставит запуски в `succeeded`.

## Данные и порядок

Телефон вызывает `POST /v1/runs`. Транзакция постановки коммитится на машине хаба так же, как для локального клиента. Дальше захват, слот, модель и сервис идут на машине хаба. К моменту HTTP сервиса туннель уже ни при чём.

На телефонной поставке порядок тот же относительно своей локальной базы: постановка коммитится до захвата, захват коммитится до модели, слот отпускается до исходящего вызова сервиса. Закрытие приложения из обработчика не вызывает `finish` со статусом `succeeded`. Потеря процесса снимает аренду обычным сроком, когда процесс снова выполнит reap.

`chat_id` сервису по-прежнему не отправляется.

## Отказы

Туннель не поднят — клиент получает отказ сети. Запуск не создаётся, потому что постановка не дошла. Дошедшая постановка живёт своей арендой, даже если телефон ушёл в сеть. Итог телефон прочитает повторным `GET`, когда путь вернётся. Новый `idempotency_key` для этого чтения не нужен. Повторный `POST` с тем же ключом вернёт ту же строку (`200`, `replay`).

Подмена назначения туннеля на чужой порт — ошибка установки. Хаб её не принимает сменой `API_LISTEN_HOST`.

Нет bearer на постановке через туннель — `401`, как с локального порта.

Потеря телефона: отозвать устройство у продукта туннеля и удалить один хеш клиента. Остальные клиенты и сервисы не перевыпускаются.

## Безопасность

Разработка. В репозиторий не кладут конфиг туннеля с ключами. Тест хаба поднимает клиент на `127.0.0.1` и не имитирует продукт туннеля. Ревью отвергает патч, который меняет `API_LISTEN_HOST` или добавляет слушатель на все интерфейсы. Ревью отвергает патч, который читает конфиг туннеля из вызова сервиса.

Эксплуатация. Оператор хранит ключи устройств в хранилище выбранного позже продукта и отдельно хранит хеши bearer. Резервная копия хаба не содержит приватный ключ туннеля в дампе базы: этому ключу в Postgres места нет.

На хосте файрвол не пускает на внешний интерфейс порты хаба и баз. Это дублёр к bind на лупбэк, не повод открыть bind.

Секреты телефонной поставки не попадают в текст модели, в журнал и в репозиторий. Хранилище ОС — единственное место сырого bearer на телефоне.

## Тесты

- процесс API не слушает `0.0.0.0`, и попытка сконфигурировать такой хост падает до `listen`;
- запрос без bearer на `127.0.0.1:8787` получает `401` на `POST /v1/runs`;
- `GET /health` с лупбэка остаётся `200`;
- в коде вызова сервиса нет адреса телефона и нет чтения конфига туннеля;
- отзыв одного хеша не меняет второй;
- заголовок `Host`, отличный от `127.0.0.1`, не принимается текущей проверкой URL;
- обработчик сигнала воркера не ставит `succeeded`.

Живой телефон и живой туннель в `npm test` не требуются.

## Критерии готовности

Контракт сервиса не упоминает туннель. Хаб на машине слушает только `127.0.0.1`. Продукт туннеля в документе не выбран. Телефон не становится обязательным входящим адресом для сервисов. Телефонная поставка хаба не открывает входящий слушатель для чужих сервисов, держит один слот и один воркер и кладёт секреты в хранилище ОС. Стек UI не выбран.
