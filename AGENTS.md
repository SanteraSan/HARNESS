# HARNESS — вход для агентов

Репозиторий: `/home/santera/ALL PROJECTS/HARNESS`. Продуктовый план: `docs/PLAN.md`, пока его нет в репозитории — `/home/santera/.cursor/plans/harness_local_development.plan.md`. План говорит, что строить. Правила в `.cursor/rules/` говорят, как.

Код по плану не начинается сам. Человек пишет «реализуй HARNESS» или «продолжай HARNESS». Текущий агент читает `.cursor/skills/harness-build/SKILL.md` и становится оркестратором: сам вызывает исполнителей, ревьюера и приёмку. Отдельных ботов запускать не нужно.

## Песочница

Каталог лежит вне workspace `/home/santera/Projects`. Ключ `gh` лежит в системной связке. Команда в песочнице получает отказ GitHub и может не записать файл, хотя доступ есть.

Любой `git`, `gh`, тест и правка этого репозитория запускается без песочницы (`required_permissions: ["all"]`). Повторный отказ из песочницы не повод менять план, remote или способ аутентификации.

## Кто ты

- В задании написано «оркестратор» — читай `.cursor/rules/orchestrator.mdc`. Продуктовый код не пиши.
- В задании есть `M1-P*` — ты исполнитель одного пакета. Читай остальные правила. Чужие каталоги не трогай.
- Ревьюер сверяет дифф с планом и правилами. Новую возможность не добавляет.
- Приёмка — только пакет `M1-P9`. Красный продуктовый сценарий возвращает оркестратору.
